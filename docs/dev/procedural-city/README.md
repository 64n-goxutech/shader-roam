# 程序化城市开发文档

> ⚡ 2026-08-04：程序化城市与道路源码已删除，本文仅保留历史开发记录。

## 1. 历史方案

### V0：远景城市剪影（已交付）

- 🆕 版本基线：`motion-reference-2026-07-10.2`。
- 🆕 每栋建筑由一个实例化盒体和一个扁平屋顶灯组成。
- 🆕 CPU 生成位置、宽高深、旋转和颜色；越过回收边界后重新布置到前方。
- 🆕 建筑主体使用 `MeshBasicMaterial`，目标是低成本提供远景方向与高度参照，不表达真实楼层或立面。
- 🆕 `low` 档固定为 `48` 栋建筑，不随飞行距离增加对象数量。

## 2. V1 实施计划（本轮）

1. 🆕 保留 `MotionReferenceField`、旅行坐标系、固定实例池和回收边界。
2. 🆕 将单段楼体扩展为主体、上层退台和屋顶灯三个固定实例层。
3. 🆕 为每栋建筑生成稳定种子和体块参数，回收前不改变外观。
4. 🆕 用自定义 facade shader 生成楼层、窗格、亮灯、方向明暗和远景雾，不引入外部纹理。
5. 🆕 更新实例数量、draw layer 和 shader 状态诊断。
6. 🆕 完成 TypeScript 构建、WebGL shader 编译检查、桌面和移动视口截图验收。

## 3. 本轮约束

- 🆕 不迁移 `WebGPURenderer`；先在现有 `WebGLRenderer` 上验证城市表达与数据边界。
- 🆕 不引入道路、碰撞、城市地面或运行时地图服务；这些属于后续城市区块阶段。
- 🆕 不删除 V0 记录，也不改写已有 `motion-reference` 文档中的历史交付事实。
- 🆕 不新增 GLB、立面贴图或运行时网络资源。
- 🆕 默认 `low` 质量档必须维持固定容量和可交互性能。

## 4. 验收标准

- 建筑远看保持清晰天际线，近看能识别主体与退台层次。
- 正面与侧面出现稳定楼层/窗格，亮灯分布在建筑回收前不闪烁。
- 立面存在与落日方向一致的明暗，不再是完全平涂剪影。
- 城市仍在载具后方或超出距离时回收到前方，不持续增长场景对象。
- `npm run build` 通过，浏览器无 shader 编译错误或未处理运行时错误。
- 桌面与移动视口中城市、飞车、HUD 和天空不发生遮挡异常。
