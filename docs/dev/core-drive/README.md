# 核心驾驶开发文档

## 目标

🆕 将项目从落日城市飞行场景收缩为最小核心：只保留 AE86、车辆运动、车轮动画、输入控制和跟随相机，优先恢复清晰的车辆观感与稳定交互。

## 实施计划

1. 🆕 从 `Experience` 移除环境与运动参照模块的创建、逐帧更新、resize、dispose 和诊断链路。
2. 🆕 删除体积云、程序化城市、道路和运动参照源文件。
3. ⚡ 将配置缩减为车辆加载所需字段，移除环境名与质量档。
4. 🆕 删除 HUD 与落日调试 API，只保留通用运行时快照和帧缓冲 dump。
5. 🆕 使用中性清屏色和最小基础灯光显示车辆，不加入新的场景装饰。
6. ⚡ 统一车辆、车轮和相机的帧时，避免超过 `33ms` 后直接丢弃运动时间。
7. 🆕 完成构建、资源加载、桌面/移动画面、输入运动和 renderer 指标验证。

## 验收标准

- Scene 中除车辆根节点与基础灯光外没有天空、云、地面、建筑或程序化参照节点。
- 页面不显示环境 HUD，也不暴露 atmosphere shader 调试入口。
- AE86 加载成功，四个车轮保持绑定和旋转。
- 按键输入会改变车辆位置、速度或姿态，相机持续跟随。
- renderer draw calls、三角形和 shader program 数量显著低于旧场景。
- `npm run build` 通过，桌面与移动视口无运行时错误和画面重叠。

## 当前状态

- ⚡ 2026-08-04：最小运行时已落地并完成构建、桌面/移动画面和输入运动验证。

## 实际落地

- 🆕 删除 `SunsetEnvironment`、`MotionReferenceField`、`sunsetSky` 和 `proceduralCity`，源码减少约 `2,300` 行。
- ⚡ `Experience` 的 Scene 子节点固定为车辆根节点、车辆填充灯和车辆主光，不再存在环境更新或 resize/dispose 链路。
- ⚡ `ExperienceConfig` 只保留车辆 ID、模型 URL 与视觉 yaw；页面只保留一个全屏 canvas。
- ⚡ renderer 使用纯色 `#111318` 背景、DPR `1` 和基础抗锯齿；相机初始偏移由 `(0, 2.7, 13.5)` 收近至 `(0, 2.25, 9.5)`。
- ⚡ 帧时上限由 `1/30s` 放宽为 `0.1s`；正常长帧继续推进真实运动时间，只过滤标签恢复等异常大步长。
- 🆕 debug API 收缩为 `snapshot()` 与 `dump()`，诊断仅包含运行时、车辆、相机、renderer、Scene 子节点和可选帧缓冲采样。
